# MarketPulse 小程序实施计划

## 1. 建立实施基线

执行指令：阅读 `design-document.md`、`tech-stack.md` 和现有 `src/` 脚本，确认现有 HTML 看板、SQLite 数据库、payload 生成函数和测试入口。不要修改现有 HTML 输出路径和模板行为。

验证测试：运行现有测试套件，确认全部通过；分别执行两个现有看板脚本，确认仍能生成原有 HTML 文件。

## 2. 梳理 payload 字段契约

执行指令：为 `ashare` 和 `beijing` payload 建立字段清单，覆盖所有小程序 tab 所需 section，并记录字段来源、数组层级、日期字段、数值字段和表格字段。

验证测试：用本地数据库生成两类 payload，并逐项核对字段清单中的 section 均存在；确认字段清单没有包含网页看板之外的新指标。

## 3. 增加 payload 上传目录与说明

执行指令：新增 `api/` 目录规划，放置上传脚本、云函数目录和简短说明文档。说明本地 Python 负责生成 JSON，云函数只负责读取和裁剪。

验证测试：检查目录结构符合设计文档建议；确认新增目录不影响 `python3 -m pytest`。

## 4. 实现 payload 生成与序列化脚本

执行指令：新增 `api/upload_payload.py`，复用两个现有 `build_dashboard_payload()`，支持指定数据库、起始日期、目标日期和云环境参数；先完成本地 JSON 生成能力，再接入上传。`--start-date` 只用于传递给现有 payload 生成流程，控制历史数据读取或计算起点；输出 payload 的文件日期使用业务数据最新日期。

验证测试：对比脚本生成的 `ashare` JSON 与 `src/security_market_pulse.py` 的 payload 完全一致；对比 `beijing` JSON 与 `src/beijing_real_estate_market_pulse.py` 的 payload 完全一致；确认 JSON 严格序列化时不包含 NaN 或 Infinity；确认输出文件名日期来自业务数据最新日期而非脚本运行日期或 `--start-date`。

## 5. 接入微信云存储上传

执行指令：让上传脚本把 JSON 上传到非公开云存储目录，文件命名使用 `marketpulse-payload/{type}_{date}.json` 规则，并保留清晰日志。上传实现预留腾讯云 COS、微信云开发 CLI 或微信开发者工具 CLI 接入；上传 payload 后同步维护 `marketpulse-payload/manifest.json`，记录 `ashare` 和 `beijing` 的最新文件及可用日期。

验证测试：云环境就绪前，验证本地生成的 payload 文件和 manifest 内容正确；云环境就绪后，在测试云环境上传一组 `ashare` 和 `beijing` JSON，确认文件存在、文件名日期正确、manifest 指向最新文件、内容可由服务端读取；确认小程序端不能直接拿到公开下载地址。

## 6. 创建云函数骨架

执行指令：新增 `api/cloudfunctions/getDashboardSection/`，使用 Node.js 云函数运行时，接收 `type`、`section` 和可选 `date`，并获取调用者登录上下文。云函数侧只以调用上下文中是否存在 `OPENID` 判断访问状态；没有 `OPENID` 返回可处理错误，有 `OPENID` 即允许访问。

验证测试：本地或云端调用云函数，确认缺少 `OPENID` 或身份上下文异常时返回可处理错误；确认存在 `OPENID` 的调用能进入后续读取流程。

## 7. 实现 section 白名单映射

执行指令：在云函数内维护固定白名单，只允许设计文档列出的 `ashare` 和 `beijing` section；复合 section 只返回当前 tab 必需字段组合。

验证测试：逐个请求所有合法 section，确认均返回对应数据；请求不存在的 section 和错误 type，确认返回错误且不泄露完整 payload。

## 8. 实现最新文件回退

执行指令：云函数读取指定日期 JSON；未指定日期时通过 `marketpulse-payload/manifest.json` 读取最新可用 JSON；指定日期不存在时根据 manifest 回退到最近可用版本。不要依赖云存储前缀枚举作为第一版回退机制。

验证测试：准备多个日期文件和 manifest，分别验证指定日期、无日期、缺失日期三种场景；确认回退选择的是 manifest 中记录的最近可用版本。

## 9. 增加云函数响应约束

执行指令：确保云函数响应只包含 `type`、`section`、当前 section 数据和必要错误信息；不得返回云存储路径、`fileID`、下载凭据或完整 dashboard payload。

验证测试：对每个 section 做响应字段检查；确认响应中不存在非当前 tab 字段；确认无法通过参数绕过裁剪。

## 10. 初始化微信原生小程序工程

执行指令：创建 `miniprogram/` 工程，包含全局配置、首页、资本市场页、北京楼市页、工具目录和 ECharts 组件目录。直接将 ECharts for 微信 `ec-canvas` 组件源码放入 `miniprogram/components/ec-canvas/`。允许新增 `miniprogram/project.config.json`，但不得写入真实 `appid`、`env-id` 或敏感配置。不要引入跨端框架、大型 UI 库或前端状态管理库。

验证测试：云环境就绪前，用微信开发者工具打开项目，确认编译无错误；首页能作为启动页显示；检查 `project.config.json` 不包含真实敏感配置。

## 11. 实现登录流程

执行指令：封装登录工具，页面进入时展示授权按钮并获取头像昵称，完成微信登录后回到原目标页；第一版只做身份识别，不做角色和权限分层。

验证测试：清除本地登录状态后进入首页、资本市场页、北京楼市页，确认都能看到授权入口、完成头像昵称授权和登录并回到目标页面；模拟授权拒绝或登录失败时确认可重试且不出现空白屏。

## 12. 实现首页与分享入口

执行指令：实现总览首页，只展示“资本市场”和“北京楼市”两个入口，并支持分享首页。首页不加载全部图表数据。

验证测试：点击两个入口分别进入对应看板；分享首页后打开路径仍为首页；抓取请求记录，确认首页未请求所有图表 section。

## 13. 实现请求与缓存工具

执行指令：封装云函数请求工具和 section 缓存工具。缓存键按 `type` 和 `section` 区分，有效期 24 小时；请求成功写缓存，请求失败尝试有效缓存。

验证测试：首次请求命中云函数并写入缓存；重复进入同一 section 优先使用内存或缓存；模拟网络失败时能读取有效缓存；缓存过期时进入错误处理。

## 14. 实现资本市场页面结构

执行指令：资本市场页使用横向 tab 或分段控件组织四个 section：指数 MA60 偏离、A 股融资余额、A 股成交金额、A 股成交集中度；进入页面只请求默认 tab。

验证测试：首次进入只请求一个默认 section；切换四个 tab 时分别请求对应 section；重复切回已加载 tab 不产生无意义重复请求。

## 15. 实现北京楼市页面结构

执行指令：北京楼市页使用横向 tab 或分段控件组织五个 section：看房人数、跌涨比、大中介成交、网签量、居民贷款；居民贷款内部使用二级 tab。

验证测试：首次进入只请求默认 section；切换五个主 tab 和居民贷款二级 tab 时页面稳定；每次只渲染当前 tab 所需内容。

## 16. 建立图表 option 构造层

执行指令：在 `miniprogram/utils/echarts-option.js` 集中维护所有图表配置构造逻辑，统一颜色、坐标轴、tooltip、金额、百分比、参考线和最新值表达。图表一致性以数据和语义一致为准，不做像素级复刻。

验证测试：用固定 payload 样本生成每类图表配置，核对标题、轴含义、单位、序列数量、参考线和格式化结果与网页语义一致；不以像素级截图一致作为第一版验收条件。

## 17. 渲染资本市场图表和表格

执行指令：渲染指数 MA60 偏离、融资余额、融资余额占比、成交金额双轴图、top5% 成交集中度图和最近 5 个交易日 Top5 股票表。表格必须在手机端可横向或分组查看。

验证测试：抽样核对每个图表最后一个点、关键参考线和表格最近 5 个交易日数据与 payload 一致；在常见手机宽度下确认图表和表格不截断。

## 18. 渲染北京楼市图表

执行指令：渲染看房人数 weekday 分组、跌涨比、链家成交 weekday 分组、日度网签、月度网签、居民贷款同比、当月净增和年内累计净增。

验证测试：逐项核对 weekday 分组顺序、日期、数值、趋势和参考线与 payload 一致；确认居民贷款二级 tab 不一次性堆叠全部图表。

## 19. 实现下拉刷新

执行指令：资本市场页和北京楼市页支持下拉刷新；刷新时只重新请求当前 tab 的 section，并在完成后停止下拉状态。

验证测试：在每个主 tab 执行下拉刷新，确认只刷新当前 section；云函数失败时页面不空白，并按缓存或错误态处理。

## 20. 实现错误态与重试

执行指令：覆盖云函数失败、云存储文件不存在、section 结构异常、缓存不存在或过期四类错误。错误态保持页面结构稳定，允许展示简短文案，并提供重试入口。

验证测试：分别模拟四类错误，确认文案克制且可理解、页面不崩溃、重试能重新发起当前 section 请求。

## 21. 实现看板页分享

执行指令：为首页、资本市场页、北京楼市页配置分享标题和路径；第一版分享到看板页即可，不要求落到具体 tab。

验证测试：分别分享三个页面，接收端打开后进入正确页面；未登录接收端先登录再进入分享目标页。

## 22. 做端到端数据一致性验收

执行指令：使用同一份本地数据库生成网页 HTML、上传 JSON，并通过小程序读取云函数 section 数据。逐项比对小程序展示与网页 payload。云环境就绪前，先用本地 JSON 和 Mock/本地云函数响应完成同口径数据一致性验证。

验证测试：完成资本市场 4 个 section 和北京楼市 5 个 section 的数值核对；确认云函数没有新增、删除或改写业务字段含义。

## 23. 做移动端兼容验收

执行指令：在微信开发者工具和至少两个常见手机宽度下检查首页、两个看板、图表卡片、横向表格、二级 tab、加载态和错误态。

验证测试：确认无内容截断、无布局重叠、无空白屏、图表可读、表格可查看全部列。

## 24. 完成上线前安全检查

执行指令：检查云存储权限、云函数返回内容、环境变量和本地配置文件，确保密钥、`.env`、私有数据库和下载凭据不会进入小程序包或响应体。

验证测试：搜索项目中的敏感配置痕迹；抓取云函数响应样本，确认不包含 `fileID`、云存储路径、下载链接、token 或完整 payload。
