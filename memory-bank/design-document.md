# MarketPulse 微信小程序产品设计文档

## 1. 项目背景

`MarketPulse` 当前已经具备本地数据更新、SQLite 数据存储和静态 HTML 看板生成能力。现有能力包括：

- `src/security_market_pulse.py`：生成资本市场看板，包含指数 MA60 偏离、A 股融资余额、A 股成交金额、A 股成交集中度。
- `src/beijing_real_estate_market_pulse.py`：生成北京楼市看板，包含看房人数、跌涨比、大中介成交、网签量、居民贷款。
- 两个 HTML 看板均通过 `build_dashboard_payload()` 生成结构化 payload，再把 payload 注入页面渲染。

本次产品目标是在不影响现有 HTML 生成功能的前提下，新增微信小程序形态，让用户可以在手机端查看同一批指标数据。小程序不重写现有 Python 数据采集和 HTML 生成逻辑，而是复用当前 payload 生成能力，将 JSON 上传至微信云存储，再由小程序通过云函数读取并渲染。

## 2. 产品定位

MarketPulse 小程序是一个只读型市场数据看板，面向移动端快速查看市场状态。

第一版重点不是增加新的数据指标，而是将现有两个网页看板迁移到微信小程序，并针对手机屏幕做信息层级优化。用户进入小程序后先看到总览首页，再进入“资本市场”或“北京楼市”看板查看详细图表。

## 3. 产品目标

### 3.1 核心目标

- 复用现有 Python 数据流水线和 payload 生成函数。
- 保留当前 HTML 看板生成能力，不修改现有 HTML 输出行为。
- 新增微信小程序，提供总览首页、资本市场看板、北京楼市看板。
- 在移动端以更适合手机阅读的层级展示图表和表格。
- 支持用户登录，但第一版暂不做权限控制。
- 支持小程序分享给他人。
- 支持进入页面拉取数据、下拉刷新、缓存兜底和错误态展示。
- 验收时确保小程序数据与网页 payload 一致，关键图表视觉与数值一致。

### 3.2 非目标

- 不重写现有 Python 数据采集逻辑。
- 不修改当前生成 HTML 的功能、模板和输出路径。
- 不把 Python 数据处理逻辑迁移到云函数。
- 不新增网页看板没有的市场指标。
- 不做复杂用户权限、角色、收藏、订阅和个性化配置。
- 不做盘中实时行情。
- 不做图表缩放、框选、复杂交互分析工具。
- 不做深色模式。

## 5. 用户与场景

### 5.1 目标用户

- 关注 A 股市场状态的个人用户。
- 关注北京楼市成交、挂牌、看房和信贷变化的个人用户。
- 需要在手机上快速查看 MarketPulse 看板的人。

### 5.2 典型场景

- 用户打开小程序，先在总览首页选择要查看的看板。
- 用户进入资本市场看板，查看指数偏离、融资余额、成交金额和成交集中度。
- 用户进入北京楼市看板，查看看房、成交、网签和居民贷款指标。
- 用户在微信中把小程序分享给他人，对方打开后可登录并查看同样的数据看板。
- 网络异常时，小程序优先展示本地缓存数据；没有缓存时展示错误态。

## 7. 页面设计

### 7.1 总览首页

总览首页是小程序首屏，不直接堆叠所有图表，只提供两个主要入口：

- 资本市场
- 北京楼市

首页应突出两个看板的业务边界，避免把所有指标压缩到首屏。每个入口可展示简短名称和当前可用状态，但不展示数据日期、生成时间、缓存提示等辅助信息。

交互要求：

- 点击“资本市场”进入资本市场看板。
- 点击“北京楼市”进入北京楼市看板。
- 页面可被分享。
- 未登录用户进入小程序时触发登录流程，登录后回到当前页面。

### 7.2 资本市场看板

资本市场看板包含 4 个子 tab：

1. 指数MA60偏离
2. A股融资余额
3. A股成交金额
4. A股成交集中度

移动端展示原则：

- 顶部使用横向 tab 或分段控件切换指标。
- 单屏优先展示当前 tab 的核心图表，不跨 tab 混排。
- 图表卡片纵向排列，保证手机端可读性。
- 表格类内容允许横向滚动，避免压缩列宽导致不可读。

#### 指数MA60偏离

展示现有 payload 中的 `indexDeviation` 数据。

要求：

- 按现有指数顺序展示。
- 每个指数一张图表卡片。
- 图表数值、折线趋势、参考线和网页保持一致。
- 移动端纵向滚动查看多张指数图。

#### A股融资余额

展示现有 payload 中的 `margin` 数据。

要求：

- 展示融资余额图。
- 展示融资余额占流通市值比例图。
- 数值格式、百分比格式和网页保持一致。

#### A股成交金额

展示现有 payload 中的 `turnover` 数据。

要求：

- 展示沪深成交金额与沪深 300 点位双轴图。
- 左轴为成交金额，右轴为沪深 300 点位。
- 图表趋势、双轴含义和网页保持一致。

#### A股成交集中度

展示现有 payload 中的 `topConcentration` 数据。

要求：

- 第一部分展示 top5% 成交集中度折线图。
- 第二部分展示最近 5 个交易日的 Top5 股票表。
- Top5 股票表包含股票名称、成交金额、涨跌幅。
- 表格在手机端使用横向或分组滚动展示，保证列内容可读。

### 7.3 北京楼市看板

北京楼市看板包含 5 个子 tab：

1. 看房人数
2. 跌涨比
3. 大中介成交
4. 网签量
5. 居民贷款

移动端展示原则：

- 顶部使用横向 tab 或分段控件切换指标。
- weekday 类图表按工作日或周末分组纵向排列。
- 居民贷款内部可继续使用二级 tab，避免一次展示过多图表。

#### 看房人数

展示现有 payload 中的 `houseViewPeopleByWeekday` 数据。

要求：

- 按 weekday 分组展示。
- 每个分组一张图表卡片。
- 趋势和数值与网页保持一致。

#### 跌涨比

展示现有 payload 中的 `decreaseRatio` 数据。

要求：

- 展示主折线图。
- 保留网页中的关键参考线含义。
- 数值和趋势与网页保持一致。

#### 大中介成交

展示现有 payload 中的 `lianjiaDealsByWeekday` 数据。

要求：

- 按 weekday 分组展示。
- 每个分组一张图表卡片。
- 趋势和数值与网页保持一致。

#### 网签量

展示现有 payload 中的 `dailyOnlineSignings` 和 `monthlyOnlineSignings` 数据。

要求：

- 展示日度网签量图。
- 展示月度网签量图。
- 保留网页中的关键参考线含义。

#### 居民贷款

展示现有 payload 中的 `creditYoy`、`loanNetIncreaseByMonth`、`totalLoanNetIncreaseByMonth` 数据。

要求：

- 使用二级 tab 展示：
  - 同比
  - 当月净增
  - 年内累计净增
- 月度卡片纵向排列。
- 每张图的年份、月份、数值与网页保持一致。

## 8. 登录设计

第一版需要用户登录，但不做权限控制。

登录目标：

- 识别用户身份，满足小程序基础用户体系要求。
- 为后续权限控制、订阅、个人配置预留能力。
- 不影响当前只读看板使用。

登录口径：

- 未登录用户进入小程序时触发微信登录。
- 登录成功后进入原目标页面。
- 登录失败时允许用户重试。
- 第一版不区分用户角色，所有登录用户可查看同样内容。

## 10. 数据与系统设计

### 10.1 总体链路

```text
本地/服务器 Python
  ├── src/security_market_pulse.py
  └── src/beijing_real_estate_market_pulse.py
          │
          ▼
build_dashboard_payload()
          │
          ▼
upload_payload.py 上传 JSON
          │
          ▼
微信云存储
          │
          ▼
云函数 getDashboardSection
          │
          ▼
微信小程序页面渲染
```

### 10.2 复用原则

- 复用 `security_market_pulse.py` 的 `build_dashboard_payload()`。
- 复用 `beijing_real_estate_market_pulse.py` 的 `build_dashboard_payload()`。
- 复用现有 SQLite 数据库。
- 复用现有格式化、颜色、图表含义和指标定义。
- 不修改现有 HTML 生成逻辑。
- 小程序只通过云函数消费当前 tab 所需 JSON 数据，不直接访问数据库和外部数据源。
- 小程序端不直接获取云存储 `fileID`，也不通过 `fileID` 下载 JSON 文件。
- 云存储 JSON 文件只允许云函数读取，不对小程序端或公网开放直接下载权限。

### 10.3 Payload 类型

云存储中至少保留两类 payload：

| 类型 | 文件含义 | 来源 |
|---|---|---|
| `ashare` | 资本市场看板 payload | `src/security_market_pulse.py` |
| `beijing` | 北京楼市看板 payload | `src/beijing_real_estate_market_pulse.py` |

文件命名建议：

```text
marketpulse-payload/ashare_YYYY-MM-DD.json
marketpulse-payload/beijing_YYYY-MM-DD.json
```

云函数读取时支持获取最新版本。找不到指定日期文件时，回退到最近可用版本。

### 10.4 云函数返回约束

小程序不应一次性获取整个 dashboard payload。云函数必须按当前页面和当前 tab 返回裁剪后的数据。

请求参数建议：

| 参数 | 说明 | 示例 |
|---|---|---|
| `type` | 看板类型 | `ashare`、`beijing` |
| `section` | 当前 tab 对应数据段 | `indexDeviation`、`margin`、`turnover`、`topConcentration`、`houseViewPeopleByWeekday` |
| `date` | 可选，指定 payload 日期 | `2026-06-05` |

返回原则：

- 只返回当前 tab 渲染所需字段。
- 不返回完整 `ashare` 或 `beijing` dashboard payload。
- 不返回云存储文件路径、`fileID` 或可直接下载 JSON 的凭据。
- 云函数内部可读取完整 JSON 文件，但对小程序响应前必须按 `section` 裁剪。
- 如果当前 tab 需要多个字段，允许返回该 tab 的字段组合，例如“网签量”可返回 `dailyOnlineSignings` 和 `monthlyOnlineSignings`。

## 11. 刷新、缓存与错误态

### 11.1 数据加载

- 进入总览首页时不强制加载全部图表数据。
- 进入资本市场看板时，只请求当前默认 tab 对应的 section 数据。
- 进入北京楼市看板时，只请求当前默认 tab 对应的 section 数据。
- 当前看板内切换 tab 时，按新 tab 请求对应 section 数据。
- 已请求过的 section 可在本地缓存中复用，避免重复请求。

### 11.2 下拉刷新

- 资本市场看板支持下拉刷新。
- 北京楼市看板支持下拉刷新。
- 下拉刷新时重新请求云函数并刷新当前 tab 的 section 数据。
- 刷新完成后停止下拉状态。
- 不额外展示数据日期、生成时间或刷新失败提示文案。

### 11.3 缓存

- 请求成功后将当前 section 数据写入本地缓存。
- 缓存有效期建议为 24 小时。
- 网络异常时优先使用有效缓存。
- 无可用缓存时进入错误态。

### 11.4 错误态

错误态需要可用，但文案保持克制。

至少覆盖：

- 云函数请求失败。
- 云存储文件不存在。
- section 数据结构不符合预期。
- 本地缓存不存在或已失效。

错误态操作：

- 提供重试入口。
- 保持页面结构稳定，不出现空白屏。

## 12. 视觉与交互原则

### 12.1 视觉延续

小程序视觉应延续现有网页看板：

- 浅色背景。
- 绿色作为主强调色。
- 图表卡片式承载。
- 数字和图表保持清晰、克制。

### 12.2 移动端优化

- 首页不展示全部图表，先做看板入口。
- 看板内部通过 tab 分层，降低首屏信息密度。
- 图表纵向排列，避免多图横向挤压。
- 表格使用横向滚动或日期分组卡片。
- 图表标题应直接表达指标，不使用过长说明。
- 数字格式与网页一致，避免手机端出现截断。

### 12.3 图表交互

- 使用 ECharts for 微信 `ec-canvas`。
- 保留 tooltip 等基础图表交互。
- 不启用 dataZoom、brush 等复杂交互。
- 关键图表趋势、轴含义、参考线和最新值表达与网页保持一致。

## 15. 验收标准

### 15.1 数据一致性

- `ashare` payload 与 `security_market_pulse.py` 中 `build_dashboard_payload()` 输出一致。
- `beijing` payload 与 `beijing_real_estate_market_pulse.py` 中 `build_dashboard_payload()` 输出一致。
- 云函数返回的 section 数据来自对应 dashboard payload，且不新增、删除或改写业务字段含义。
- 小程序图表展示数值与网页 payload 对应字段一致。
- 小程序端无法直接获取云存储 `fileID` 或直接下载完整 JSON 文件。
- 云函数响应不包含完整 dashboard payload，只包含当前 tab 渲染所需 section 数据。

### 15.2 图表一致性

资本市场需验证：

- 指数MA60偏离图的指数顺序、趋势、百分比和参考表达与网页一致。
- A股融资余额图的数值、趋势和比例图与网页一致。
- A股成交金额双轴图的成交金额与沪深 300 点位对应正确。
- A股成交集中度图和最近 5 个交易日 Top5 股票表与网页一致。

北京楼市需验证：

### 15.3 可用性

- 未登录用户可以完成登录并进入小程序。
- 总览首页可以进入资本市场和北京楼市看板。
- 两个看板页首次进入可以正确加载数据。
- 子 tab 切换可以按需请求对应 section，不卡死、不重复无意义请求。
- 下拉刷新可以重新拉取并渲染当前 section 数据。
- 网络异常时可以使用有效缓存。
- 无缓存且请求失败时展示错误态，并可以重试。
- 分享首页或看板页后，接收者可以打开对应页面。

### 15.4 兼容性

- 在微信开发者工具中验证主要页面。
- 在常见手机宽度下验证图表和表格不发生内容截断。
- 横向滚动表格在手机端可正常查看全部列。

## 16. 实施边界

开发小程序时需要特别遵守以下边界：

- 不修改 `src/security_market_pulse.py` 和 `src/beijing_real_estate_market_pulse.py` 的现有 HTML 生成行为。
- 如需新增导出或上传能力，应通过新增脚本或新增旁路函数完成。
- 不改变现有 SQLite 表结构，除非小程序需求确实要求新增数据字段。
- 小程序端只负责展示，不负责抓取外部金融或房产数据。
- 小程序端不直接下载云存储 JSON 文件，不接收云存储 `fileID`。
- 云存储 JSON 文件只允许云函数读取。
- 云函数只负责读取云存储 JSON、按 section 裁剪并返回，不做复杂业务计算。
